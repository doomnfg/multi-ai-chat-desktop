## 課前準備（請在上課前完成）

### 步驟 1：確認帳號

Claude Code 需要 **Pro、Max、Team、Enterprise 或 Console** 帳號，免費版不包含 Claude Code。

帳號申請請洽：`[IT 窗口]`

### 步驟 2：安裝 Claude Code（Windows）

1. 按「開始」，輸入 `PowerShell`，開啟 **Windows PowerShell**
   （畫面開頭顯示 `PS C:\Users\你的名字>` 就對了）
2. 貼上下面這行指令，按 Enter：

    ```powershell
    irm https://claude.ai/install.ps1 | iex
    ```

3. 安裝完成後，**關掉 PowerShell，再開一個新的視窗**，輸入：

    ```powershell
    claude --version
    ```

    看到版本號（例如 `2.x.x (Claude Code)`）就代表安裝成功。

> - **選配**：安裝 [Git for Windows](https://git-scm.com/downloads/win)。不裝也能用，Claude Code 會改用 PowerShell 執行指令。
> - **不想用終端機？** 可以改用 [Claude 桌面 App](https://claude.com/download) 的「Code」分頁，功能相同。
> - 安裝方式以官方文件為準：https://code.claude.com/docs/en/setup

### 步驟 3：準備練習資料夾

1. 在 D 槽建立資料夾：`D:\AI-Work\練習`
2. 把講師發的 `練習題.zip` 解壓縮到這個資料夾，結果如下：

    ```
    D:\AI-Work\練習\
    ├── ex1\
    ├── ex2\
    └── ex3\
    ```

### 步驟 4：第一次啟動與登入

在 PowerShell 輸入：

```powershell
cd D:\AI-Work\練習\ex2
claude
```

第一次啟動會開啟瀏覽器，依畫面指示登入公司帳號即可。登入後輸入：

```
這個資料夾裡有哪些檔案？
```

Claude 能列出 `input` 資料夾裡的兩個 CSV 檔，就代表一切就緒。輸入 `/exit` 可以離開。

## 模組 1：Prompt 基礎

> AI 的產出品質，取決於你交代得多清楚。

### 只說一句話會怎樣？

只說「幫我寫驗收報告」，AI 不知道：

- 哪個客戶？什麼設備？
- 測了哪些項目？結果在哪裡？
- 要什麼格式？給誰看？
- 沒有數據時該怎麼辦？

結果就是格式不對、內容空泛，**甚至自己「編」出看似合理的數字**。

### 好 Prompt 的六要素

| # | 要素 | 說明 | PSD 範例 |
|---|---|---|---|
| 1 | 角色 | 請 AI 扮演誰 | 你是 PSD 資深安裝工程師 |
| 2 | 背景 | 專案、設備、目前狀況 | IBM Power 主機 1 台，已完成開機測試 |
| 3 | 任務 | 要做什麼，用動詞開頭 | 依測試記錄撰寫驗收報告 |
| 4 | 限制 | 依據什麼、不能做什麼 | 只用檔案中的數據，不可推測 |
| 5 | 格式 | 輸出長什麼樣子 | Markdown，含測試項目表格 |
| 6 | 範例 | 給一段樣本照著做 | 附上一份過去的報告當範本 |

> 六項不一定每次都寫滿，但 **「任務」和「限制」最不能少**。

### Prompt 範本（可直接複製）

```
【角色】你是……
【背景】……
【任務】請……
【限制】
- 只能使用……的資料
- 缺少的資料標示「待補」，不可自行推測
【格式】……
【範例】參考……的寫法

資訊不足時先問我，不要自己猜。
```

### 改寫前後對照

**改寫前：**

```
幫我寫驗收報告
```

**改寫後：**

```
【角色】你是 PSD 資深安裝工程師。
【背景】客戶 [客戶A] 新購 IBM Power 主機 1 台（AIX 7.3），已完成上架與開機測試。
【任務】依據 test_log.txt 撰寫驗收報告。
【限制】只能使用檔案中的數據；缺少的欄位標示「待補」，不可自行推測。
【格式】Markdown：設備資訊、測試項目表格（項目／結果／備註）、異常與待辦、結論。
【範例】參考 sample_report.md 的寫法。
```

### 三句馬上見效的話

把這幾句加在 Prompt 最後：

| 技巧 | 加這一句 | 效果 |
|---|---|---|
| 資訊不夠，先問我 | 「資訊不足時先問我，不要自己猜。」 | 避免 AI 自己編內容 |
| 一次走一步 | 「先列出大綱給我確認，再寫內容。」 | 方向錯了，早一點發現 |
| 要它自我檢查 | 「完成後逐項對照來源檔，列出你不確定的地方。」 | 讓錯誤自己浮出來 |

## 模組 2：Claude Code 工作 SOP

> 交代清楚、讓 AI 動手、由你把關。

### 聊天式 AI 與 Agentic AI

| | 聊天式 AI | Agentic AI（Claude Code） |
|---|---|---|
| 比喻 | 打電話問顧問 | 派一位助理坐到你的辦公桌 |
| 互動 | 你問一句，它答一句 | 你交代任務，它自己規劃步驟 |
| 檔案 | 要自己複製、貼上 | 直接讀寫資料夾裡的檔案 |
| 結果 | 要自己整理、存檔 | 會執行、檢查，並回報進度 |

### 常用操作

| 操作 | 用途 |
|---|---|
| `claude` | 在目前的資料夾啟動 Claude Code |
| 直接輸入中文 | 交代任務，就像跟同事說話 |
| `@檔名` | 指定要它讀的檔案，例如 `@input/點收清單.csv` |
| `Shift + Tab` | 切換模式：一般 → 自動接受編輯 → Plan Mode |
| `Esc` | 中斷 AI 正在做的事 |
| `/clear` | 清除對話，開始新的任務 |
| `/init` | 自動產生 CLAUDE.md 專案說明書 |
| `/skills` | 列出目前可以用的 Skill |
| `/exit` | 離開 Claude Code |

> **只在工作資料夾裡啟動**，不要在桌面或磁碟根目錄啟動，避免 AI 讀到不相關的檔案。

### CLAUDE.md：給 AI 的專案說明書

- 放在工作資料夾最上層，檔名 `CLAUDE.md`
- Claude 每次啟動都會自動讀取
- 寫一次，之後不必每次重講
- 可以先用 `/init` 產生，再自行補充

**範本：**

```markdown
# 專案：[客戶A] 機房設備建置

## 設備
- IBM Power [機型] × 2（AIX 7.3）
- x86 伺服器 × 4（RHEL 9）

## 工作規則
- 一律使用繁體中文，日期格式 YYYY/MM/DD
- 序號、數量只能引用檔案內容，不可推測
- 產出檔案放在 output/ 資料夾
- 不可修改或刪除 input/ 的原始檔
```

### Agentic 工作 SOP：六個步驟

| 步驟 | 名稱 | 做什麼 | 誰負責 |
|---|---|---|---|
| 1 | 備料 | 把清單、log、範本放進工作資料夾 | 你 |
| 2 | 交代 | 用六要素 Prompt 說清楚任務 | 你 |
| 3 | 看計畫 | Plan Mode：AI 先提計畫，你確認或修改 | **你把關** |
| 4 | 放行執行 | AI 讀檔、比對、產出，每個動作經你允許 | AI 執行 |
| 5 | 驗證 | 抽查數字、序號是否與來源一致 | **你把關** |
| 6 | 修正收尾 | 指出問題讓 AI 修正，滿意後存檔交付 | AI ＋ 你 |

> 第 3 步和第 5 步是人工把關點，**絕對不能跳過**。

### Plan Mode：先看計畫，再讓它動手

1. 按 `Shift + Tab` 切換到 Plan Mode
2. 交代任務，AI 只會讀資料、提出計畫，**不會修改任何檔案**
3. 檢查計畫：比對基準對不對？有沒有漏掉的步驟？
4. 計畫不對就直接打字修正，例如「比對基準改用箱號」
5. 確認後再同意執行

> 就像施工前，先審施工計畫書。

### 權限確認：每個動作都要你點頭

Claude 要建立檔案、修改檔案或執行指令時，會先詢問你。判斷原則：

| 情況 | 處理方式 |
|---|---|
| 在 `output/` 建立或修改檔案 | 可以允許 |
| 看不懂的指令 | 拒絕，請它先解釋 |
| 刪除、搬移、覆蓋原始檔 | 拒絕，先問清楚 |
| 連線到其他主機 | 一律拒絕 |

> 新手建議只選「允許這一次」，熟悉之後再考慮「這次工作階段都允許」。

### 驗證：AI 產出的是草稿

**AI 寫草稿，簽名負責的是你。** 交付前做四項抽查：

- [ ] 數量加總與來源檔一致
- [ ] 隨機抽 3 筆序號，回原檔逐字比對
- [ ] 缺少的資料都標示「待補」，沒有被補上數字
- [ ] 請 AI 列出「不確定的地方」，逐一確認

## 模組 3：Skill 設計

> 把做對一次的方法，變成一句話就能重複使用。

### Prompt、CLAUDE.md、Skill 有什麼不同？

| | Prompt | CLAUDE.md | Skill |
|---|---|---|---|
| 比喻 | 口頭交代 | 專案說明書 | 標準作業手冊（SOP） |
| 何時生效 | 只對當下這個任務 | 每次啟動自動讀取 | 需要時 AI 自己翻出來照做 |
| 放什麼 | 這次的任務內容 | 這個專案的固定規則 | 可重複的步驟、範本、檢核表 |

### SKILL.md 的結構

**存放位置：** `.claude/skills/<skill 名稱>/SKILL.md`

```markdown
---
name: acceptance-report
description: 依據驗收測試記錄產生設備驗收報告。當使用者提到「驗收報告」或提供測試記錄檔時使用。
---

# 設備驗收報告

## 步驟
1. 讀取使用者指定的測試記錄檔
2. 依 template.md 的格式填寫
3. 缺少的數據標示「待補」，不可推測
4. 完成後逐項執行檢核清單

## 檢核清單
- 測試項目數與記錄檔一致
- 所有 FAIL 項目都列入「異常與待辦」
- 序號逐字比對無誤
```

| 區塊 | 作用 |
|---|---|
| `name` | Skill 名稱，只能用英文小寫、數字與連字號；也是 `/` 呼叫時的指令名稱 |
| `description` | 做什麼＋何時使用。**AI 靠它判斷要不要叫出這個 Skill** |
| 步驟 | 照順序執行的工作流程 |
| 範本 | 同一資料夾放 `template.md`，格式就固定 |
| 檢核清單 | 完成後 AI 自我檢查的項目 |

### description 寫得好，AI 才會自己想起來

| | description | 說明 |
|---|---|---|
| ✗ 不好 | 報告工具 | 太模糊：AI 不知道它做什麼，也不知道什麼時候該用 |
| ✓ 好 | 依據驗收測試記錄產生設備驗收報告。當使用者提到驗收報告、驗收文件，或提供 test_log 檔案時使用。 | 寫清楚「做什麼」＋「什麼時候用」 |

> 小技巧：把同事平常會講的關鍵字放進去，例如：驗收、點收、竣工、交付。

### Skill 怎麼生效

- 新增或修改 Skill 後，Claude Code 通常會自動載入
- 如果 `.claude/skills` 資料夾是**啟動後才建立的**，請輸入 `/reload-skills`，或用 `/exit` 離開後重新啟動
- 輸入 `/skills` 可以看到目前可用的 Skill
- 可以讓 AI 自動判斷使用，也可以直接輸入 `/acceptance-report` 呼叫

### 哪些工作適合做成 Skill？

符合這三點就值得做：**做過三次以上**、**步驟固定**、**有範本或檢核表**。

| PSD 的 Skill 題目 | 輸入 | 產出 |
|---|---|---|
| 驗收報告產生 | 驗收測試記錄 | 設備驗收報告 |
| 到貨點收比對 | 採購清單、點收清單 | 差異報告 |
| 機房條件確認 | 設備清單與規格 | 進場前確認表 |
| 安裝 log 摘要 | AIX `errpt`、RHEL `journalctl` 輸出 | 異常摘要與建議 |
| 竣工交付清單 | 專案設備清單 | 交付文件清單 |

> 不用從零開始寫：先和 Claude 把工作做完一次，再說「把剛剛的做法整理成一個 Skill」，你負責審稿。

## 模組 4：安全規範

> AI 很好用，但客戶的資料與設備，責任在我們身上。

### 四條紅線

| 紅線 | 內容 |
|---|---|
| 機密不外流 | 帳號密碼、IP 與網路架構一律不提供；客戶名稱改用代號 |
| 不碰客戶設備 | 不讓 AI 連線操作客戶主機；AI 給的指令先在測試機驗證 |
| 數字一定核對 | 數量、序號、測試數據，一律人工比對來源檔 |
| 人負責簽核 | AI 只產出草稿；交付前由工程師確認並簽核 |

> 實際規範依公司資安政策調整：`[公司資安政策名稱]`

### 資料遮罩：交給 AI 前先替換

客戶的 log 檔常常含有主機名稱與 IP，交給 AI 前請先替換：

| 原始資料 | 替換成 |
|---|---|
| 客戶公司名稱 | 客戶A |
| 主機名稱（例如 prod-db-01） | HOST-01 |
| IP 位址 | [IP-1]、[IP-2] |
| 帳號、密碼 | 直接刪除 |

> 替換對照表自己保留，AI 產出後再換回來。

### AI 給的主機指令：先分級，再決定能不能用

| 等級 | AIX（IBM Power） | RHEL（x86） | 處理方式 |
|---|---|---|---|
| 唯讀查詢 | `lsdev`、`lspv`、`lsvg`、`errpt`、`prtconf` | `lscpu`、`lsblk`、`ip addr`、`journalctl` | 先在測試機驗證，確認輸出後使用 |
| 變更設定 | `chdev`、`mkvg`、`chfs` | `nmcli`、`systemctl enable`、`firewall-cmd` | 依安裝 SOP，經主管核可才執行 |
| 破壞性 | `rmdev`、`rmlv`、`reducevg` | `mkfs`、`dd`、`rm -rf` | **禁止直接使用 AI 產生的版本** |

> **原則：AI 可以幫你「寫」指令，但「執行」永遠由你判斷。**
> 看不懂的指令，請 AI 逐行解釋每個參數的作用，確認後才使用。

### 團隊導入：一起累積部門的 Skill 庫

1. **共用存放**：部門的 Skill 放在共用的 git 儲存庫或共用資料夾
2. **指定負責人**：每個 Skill 有負責人與修改紀錄
3. **每月分享**：例會分享一個好用的 Prompt 或 Skill
4. **回饋改善**：用了發現問題，回報負責人修正

## 常見問題

**Q1：輸入 `claude` 出現「無法辨識」？**
請關掉 PowerShell 重開一個新視窗再試。仍然不行，請參考官方說明：https://code.claude.com/docs/en/troubleshoot-install

**Q2：用 Excel 開 CSV，中文變成亂碼？**
練習題的 CSV 已經處理過編碼，可以直接開啟。如果是自己的檔案出現亂碼，請在 Excel 選「資料 → 從文字/CSV」，編碼選 UTF-8。

**Q3：同樣的 Prompt，兩次結果不一樣？**
這是正常的，AI 每次的用詞會有些差異。只要數字與結論正確即可；要讓格式固定，就用範本或 Skill。

**Q4：AI 做到一半方向錯了怎麼辦？**
按 `Esc` 中斷，直接打字告訴它哪裡不對。如果越改越亂，用 `/clear` 清除對話，改好 Prompt 再重來。

**Q5：可以把客戶的真實資料交給 AI 嗎？**
請遵守模組 4 的四條紅線：先遮罩，再提供。不確定能不能給的，就不要給，先問主管。
