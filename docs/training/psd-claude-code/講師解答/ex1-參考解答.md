# 練習 1 參考解答：改寫 Prompt — 進場前機房條件確認表

> 講師專用，不要發給學員。

## 參考 Prompt

```
【角色】你是 PSD 資深安裝工程師，負責大型主機進場前的機房條件確認。
【背景】下週要到客戶「客戶A」機房安裝以下設備：
- IBM Power 主機 2 台（2U，AIX）
- x86 伺服器 4 台（2U，RHEL）
【任務】列出進場前需要和客戶確認的機房條件，做成確認表。
【限制】
- 只列出需要客戶確認或提供的項目，不要列出我方的內部作業
- 至少涵蓋：機櫃空間、電力、空調、承重、網路、搬運路線、進場管制
- 設備的耗電量、重量等規格數值不要自己填，標示「依原廠規格確認」
【格式】Markdown 表格，欄位為：類別／確認項目／需求說明／客戶回覆（留空）／確認日期（留空）。
表格後面附一段「進場前待確認事項」清單。

資訊不足時先問我，不要自己猜。
```

## 評分表

| 項目 | 配分 | 看什麼 |
|---|---|---|
| 角色 | 10 | 有指定 AI 扮演的身分 |
| 背景 | 20 | 有寫出設備種類與數量 |
| 任務 | 20 | 用動詞清楚說明要產出什麼 |
| 限制 | 25 | 有限定範圍，且有防止 AI 自己編規格數字 |
| 格式 | 25 | 有指定表格欄位，結果能直接印出給客戶勾選 |

## 帶討論的重點

1. **原始版的常見問題**
    - 內容太籠統，像教科書的條列，不是一張可以直接用的確認表
    - 常會自己填上設備耗電量、重量等數字 → **這些數字可能是錯的**
    - 混入我方內部作業（例如「準備工具」），不是要客戶確認的事
2. **改寫版的差異**
    - 格式固定，可以直接印出
    - 規格數值留給原廠文件，不讓 AI 推測
3. **延伸問題**：如果每個專案都要做這張表，可以怎麼做？
    → 帶出模組 3 的 Skill（「機房條件確認」Skill）
