# 練習 3 參考解答：「驗收報告」Skill

> 講師專用，不要發給學員。

## 參考 SKILL.md

存放位置：`ex3/.claude/skills/acceptance-report/SKILL.md`
（同一資料夾內另放一份 `template.md`）

```markdown
---
name: acceptance-report
description: 依據設備驗收測試記錄產生驗收報告。當使用者提到「驗收報告」、「驗收文件」、「整理測試記錄」，或提供 test_log 等測試記錄檔時使用。
---

# 設備驗收報告產生

## 輸入
- 測試記錄檔（例如 test_log.txt），由使用者指定
- 報告範本：本 Skill 資料夾內的 template.md

## 步驟
1. 讀取使用者指定的測試記錄檔，列出所有測試項目
2. 讀取本 Skill 資料夾內的 template.md，依其章節與表格格式填寫
3. 基本資料與測試數據只能引用記錄檔內容
4. 記錄檔中缺少或空白的資料，一律填「待補」，不可推測
5. 所有 FAIL 與「待補」項目，都要列入「異常與待辦」
6. 依範本的判定規則填寫結論
7. 將報告存成 output/驗收報告_<設備序號>.md
8. 執行下方檢核清單，並在回覆中列出檢核結果與不確定的地方

## 檢核清單
- [ ] 測試項目總數與記錄檔一致
- [ ] PASS、FAIL、待補的數量加總等於總數
- [ ] 所有 FAIL 與待補項目都列入「異常與待辦」
- [ ] 設備序號與記錄檔逐字相同
- [ ] 報告中沒有任何記錄檔以外的數字
```

## 預期的報告重點

用 `test_log.txt` 產出的報告，應該要有：

| 檢查項目 | 正確值 |
|---|---|
| 設備序號 | 78A1B01 |
| 測試項目總數 | 10 |
| PASS | 8（T01～T05、T07～T09） |
| FAIL | 1（T06 網路卡 ent2 Link Down） |
| 待補 | 1（T10 72 小時燒機測試，結果與實測都空白） |
| 結論 | **暫緩通過**（有 FAIL 與待補項目） |

「異常與待辦」至少要有兩筆：

| 編號 | 問題說明 | 處理方式 | 負責人 | 預計完成日 |
|---|---|---|---|---|
| T06 | ent2 Link Down，疑似跳線未接妥 | 重新接線後複測 | 待補 | 待補 |
| T10 | 72 小時燒機測試無記錄 | 補做測試或補登記錄 | 待補 | 待補 |

## 常見錯誤（帶討論用）

| 錯誤 | 原因 | 修正方式 |
|---|---|---|
| T10 被填成 PASS | AI 依常理推測 | SKILL.md 步驟寫明「空白一律填待補」 |
| 負責人被填上「工程師A」 | AI 拿測試人員當負責人 | 範本已註明沒提到的負責人填「待補」，檢查 SKILL.md 有沒有要求依範本規則 |
| 結論寫「驗收通過」 | 沒有讀範本的判定規則 | 步驟中加上「依範本的判定規則填寫結論」 |
| 沒有使用 Skill | description 沒有涵蓋學員的說法 | 把常見說法加進 description |
| `/skills` 看不到新 Skill | `.claude/skills` 是啟動後才建立的 | 執行 `/reload-skills`，或重新啟動 claude |

## 延伸討論

- 如果要做 x86 / RHEL 的驗收報告，可以共用同一個 Skill 嗎？
    → 可以：範本相同，只是測試項目不同；也可以在 Skill 資料夾放兩份範本，依設備類型選用
- 這個 Skill 要怎麼分享給整個部門？
    → 放進部門共用的 git 儲存庫，每個人複製到自己的 `.claude/skills/`，並指定負責人維護
